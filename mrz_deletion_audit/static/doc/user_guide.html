Getting started

Standard Odoo keeps no trace of deleted records. Once this app is installed, every deletion of a tracked document is logged automatically: nobody has to do anything differently.

  1. Install the app. Place the mrz_deletion_audit folder in your addons path, restart Odoo, then in Apps click Update Apps List (debug mode), search Deletion Audit and click Install.
  2. Check what is tracked. On install, the app starts tracking the main business documents of the apps already installed: contacts, products, quotations and sales orders, purchase orders, invoices and bills, payments, transfers, manufacturing orders, CRM leads, projects and tasks, employees, expenses and helpdesk tickets. See them in Deletion Audit › Configuration › Tracking Rules.
  3. Give access to your auditors. In Settings › Users, open a user and set Deletion Audit to Auditor or Administrator.
  4. Review deletions. Open Deletion Audit › Deleted Records. The newest deletions are at the top.

This guide is always available in Odoo from Deletion Audit › User Guide.

Installed another app later? Its documents are not added to the tracking rules automatically. Add a rule for them, or enable Track All Business Models in the settings.

Who can see what

The app adds two access levels under Deletion Audit on the user form. The default administrator gets Administrator on install.

Access levelCan do
AuditorReads the deletion logs of the document types the user is allowed to read in Odoo. An auditor without access to Payroll, for example, never sees deleted payslips.
AdministratorReads every deletion log, sees the Technical tab, and manages the tracking rules.
Settings accessOnly Odoo administrators (Settings rights) can open the app's settings page.
Logs cannot be altered. Nobody can edit or delete a log from the interface, not even an administrator. Logs only disappear through the retention policy you set.

In a multi-company database, a log belongs to the company of the deleted record, and users only see the logs of their companies.

The two blocks at the top

  • Deleted Record: the document type, its technical model and ID, and its company. For a cascaded record, Deleted Together With links to the parent's log and Linked Through names the field that connected them.
  • Deleted By: the user, the exact time, where the deletion came from (see the table below), the IP address and the browser. If every log shows the same IP address, see Troubleshooting. Logged-in User appears when an action ran as a different user from the person logged in.

The tabs

  • Deleted Data: every field that held a value, with its label as shown in Odoo: names instead of IDs, labels instead of codes, formatted dates.
  • Attachments: the files that were attached to the record (name, type, size).
  • Cascaded Records: the child records deleted with it, such as invoice lines or order lines. Each one has its own log.
  • Technical (administrators): the user agent (the full identification sent by the browser), the request path, the transaction reference and the raw data in JSON.

The buttons

  • Cascaded: opens the child records deleted with this one.
  • Same Transaction: opens everything deleted in the same operation. Use it when a user deleted several documents at once, or when a deletion triggered others.

Where a deletion came from

OriginMeaning
User InterfaceDeleted by a user in the Odoo web interface.
External APIDeleted by an external program through XML-RPC or JSON-RPC: an integration, a script, a connector.
Website / PortalDeleted through a website or portal page.
Scheduled ActionDeleted by a scheduled action. Origin Details names it.
CascadeDeleted automatically together with its parent record. Origin Details names the parent.
System / ScriptDeleted from the Odoo shell or server code with no web request.

Finding a deleted record

The list opens with the Direct Deletions filter, which shows the records someone actually deleted and hides the child records deleted with them. Remove the filter to see everything.

Search by

Search fieldFinds
Deleted RecordThe record's name, e.g. INV/2026/00042 or Azure Interior.
Deleted Data ContainsAny value the record held: an email, a phone number, a reference, an amount, a product name. Field labels are not searched, only values.
Document Type / Technical ModelAll deletions of one kind of document.
Deleted ByAll deletions by one user.
Record IDA record you only know by its ID, e.g. from an error message or an old link.
IP AddressEverything deleted from one computer or server.

Filters and grouping

  • Filters: Direct Deletions, Cascaded, Deleted by Me, User Interface, External API, Scheduled Actions, and Deletion Date (this month, last quarter, a custom range…).
  • Group by: Document Type, Deleted By, Origin, Deletion Date and Company.
Example. "Who deleted the contact with the email info@acme.com?" Type info@acme.com, pick Search Deleted Data Contains, and the log shows the user, the date and everything the contact held.

Analysis

Deletion Audit › Analysis opens a chart of deletions per day, split by user, with a pivot table of document types per month. It helps you spot unusual activity: one user deleting far more than usual, a sudden batch of deletions through the API, or a scheduled action removing more than expected.

Every search, filter and grouping from the list works here too. The same views are available from Deleted Records through the view switcher.

Choosing what to track

Tracking rules live in Deletion Audit › Configuration › Tracking Rules (Administrators). There is one rule per document type.

OptionWhat it does
ModelThe document type, e.g. Sales Order.
Mode: TrackEvery deletion of this document type is logged.
Mode: IgnoreDeletions of this type are never logged, even with Track All Business Models on or when they are deleted along with a parent.
Capture Cascaded RecordsAlso log the child records deleted with it, such as order lines. On by default.
Excluded FieldsFields never stored in the log. Use it for sensitive data such as a salary or a personal ID number.

The Deletions button on a rule opens that document type's logs. To pause tracking without losing the rule's settings, archive the rule.

Settings & retention

Open Deletion Audit › Configuration › Settings. Changing these requires Odoo administrator rights.

Track All Business Models

Logs the deletions of every document type, not only those with a rule. Technical data (system logs, messages and followers, sessions, access tokens, configuration parameters…) is skipped. Use Ignore rules to leave out other types.

Cascaded Records

The maximum number of child records captured for one deletion. The default is 10,000. When a deletion goes over it, the log shows a warning that only part of the children was captured.

Keep Logs For

Logs older than this number of days are deleted automatically once a day by the scheduled action Deletion Audit: Purge Old Logs. 0 keeps them forever (default). Set a limit if your data-protection rules require one.

What is captured, and what is not

Captured

  • Every stored field that held a value
  • Names of linked records (customer, product, salesperson…)
  • Tags and lines: the first 50 names, and the count of the rest
  • Long texts up to 10,000 characters (longer ones end with …)
  • Images and files stored in fields: their size only
  • The list of attachments (name, type, size)
  • The record as it was before the deletion started

Never stored

  • Fields whose technical name contains password, secret, token or api_key
  • Fields excluded in a tracking rule
  • The content of attachment files

Not logged

  • Deletions that fail. If Odoo refuses a deletion (e.g. a posted invoice), no log is kept.
  • Records archived instead of deleted. Some documents are archived, not deleted, when you click Delete. Nothing was deleted, so nothing is logged.
  • Wizards and temporary data, and records removed while a module is being installed, upgraded or uninstalled.
  • Deletions made directly in the database with SQL, bypassing Odoo.
Good to know. Some documents clean up their own children before being deleted: a transfer cancels its stock moves first. The transfer is logged as it was, but its moves are logged when they are deleted, so they appear as Cancelled.

Troubleshooting

I deleted a record but there is no log

Check that its document type has a Track rule, or that Track All Business Models is on and there is no Ignore rule for it. Also check the Direct Deletions filter: if the record was deleted along with a parent, it is listed under Cascaded. Finally, make sure the record was really deleted and not archived.

I don't see the Deletion Audit menu

Your user needs the Auditor or Administrator access level under Deletion Audit on the user form. Reload the page after the change.

An auditor cannot find a log that I can see

Auditors only see logs of the document types they can read in Odoo. Give them read access to that app, or the Administrator level.

Every log shows the same IP address, such as 127.0.0.1

Odoo sees the address of the machine that connects to it directly. If you open Odoo on the server itself, that is 127.0.0.1. If Odoo runs behind a reverse proxy (nginx, Apache, a load balancer), it is the proxy's address for every user. To record each user's real address:

  1. In the Odoo configuration file, add: 
    proxy_mode = True
  2. Make the proxy send the user's address and the host name. Odoo ignores the forwarded address when X-Forwarded-Host is missing. For nginx, in the location blocks that pass requests to Odoo: 
    proxy_set_header X-Forwarded-Host  $host;
proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
proxy_set_header X-Forwarded-Proto $scheme;
proxy_set_header X-Real-IP         $remote_addr;
  3. Restart Odoo and reload the proxy. New deletions record the real address; existing logs keep the one they recorded.

Only turn on proxy_mode when Odoo is reachable through the proxy alone. Otherwise anyone connecting directly could send a fake address.

Why does the User Agent mention Mozilla, Safari and Chrome at once?

For historical reasons, every browser names other browsers in its identification so old websites don't block it. Chrome, for example, sends Mozilla/5.0 … (KHTML, like Gecko) Chrome/147 Safari/537.36. The Browser field shows the real one, e.g. Chrome 147 on Linux; the Technical tab keeps the original text.

A log shows fewer child records than were deleted

The deletion went over the Cascaded Records maximum and the log shows a warning. Raise the limit in the settings for future deletions.

A log says “The data of this record could not be captured”

Something went wrong while reading the record. The deletion itself still went through, and who, when and where are still logged. Contact support with the document type so it can be fixed.

For developers

The app records deletions from the standard unlink() method, so custom modules are covered without any change. To delete without logging, for example in a data-cleaning script, pass this context key:

records.with_context(mrz_deletion_audit_skip=True).unlink()

Logs are stored in mrz.deletion.audit.log and rules in mrz.deletion.audit.rule. The snapshot is a JSON field keyed by field name:
